# Навигатор по корпоративным регламентам — MVP

Прототип поиска с реестром документов, фильтрацией по подразделению, разговорным ответом со ссылками на документы/разделы и обезличенными сигналами качества. Полные тексты четырёх предоставленных документов лежат локально в `data/source_docs/` и исключены из Git. Перед запуском в другом окружении поместите туда разрешённые тексты с именами, указанными в `data/registry.json`.

## Запуск

Требуется Node.js 24+ (используется встроенный `node:sqlite`).

1. Скопировать `.env.example` в `.env` и задать `POLZA_RUNTIME_API_KEY`.
2. `node server.js`
3. Открыть `http://127.0.0.1:3000`.

## Переносимый запуск на сервере

В комплекте есть `Dockerfile`, `compose.yaml` и `deploy.sh`. Для Linux-сервера нужны Docker Engine и Bash. Перед запуском предоставьте разрешённые тексты в `data/source_docs/` и локальный реестр `data/registry.json`, создайте `.env` из `.env.example`, задайте ключ Polza и `QUALITY_ADMIN_TOKEN`, затем выполните `sudo ./deploy.sh` (порт по умолчанию 3210; можно сменить через `APP_PORT=...`). Скрипт использует обычный Docker CLI и не зависит от установленной версии Compose. Для отдельного кандидата используйте `APP_CONTAINER=process-compass-candidate APP_IMAGE=process-compass-mvp:candidate APP_PORT=3211 ./deploy.sh`; основной контейнер на 3210 при этом не заменяется. Стенд проверяется по `http://<адрес-сервера>:<порт>/api/health`. SQLite, обращения в службу качества, логи и проверенный опыт хранятся в `state/` отдельно от кода и переживают пересборку образа. `.env`, state и исходники документов не публикуйте в открытом репозитории. `compose.yaml` также есть для систем с Docker Compose V2.

Без ключа поиск по источникам работает, но модель не формирует ответ: бот предлагает передать вопрос в службу качества. Не запускайте стенд с тестовым или раскрытым ключом.

## Переменные окружения

`POLZA_RUNTIME_API_KEY`, `POLZA_BASE_URL` (по умолчанию `https://polza.ai/api/v1`), `POLZA_MODEL` (по умолчанию `qwen/qwen3.8-flash`), `PORT`, `HOST`, `STATE_DIR`, `DB_PATH`, `QUALITY_ADMIN_TOKEN`, `QUALITY_EMAIL`, `GMAIL_SMTP_USER`, `GMAIL_APP_PASSWORD`, `GMAIL_SMTP_HOST`, `GMAIL_SMTP_PORT`, `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL`, `EMBEDDINGS_API_KEY`.

Документы индексируются в локальную SQLite-базу: `documents` хранит метаданные и хеш источника, `chunks` — секционные фрагменты размером до ~1600 символов и поля `embedding_json`, `embedding_model`, `embedding_dim`. Изменившиеся документы переиндексируются по SHA-256. Чтобы включить гибридный поиск, задайте `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL` и при необходимости `EMBEDDINGS_API_KEY`: сервер построит векторы новых/изменённых чанков и сохранит их в SQLite; на запрос посчитает embedding вопроса и объединит cosine similarity с лексическим ранжированием. Для Polza используйте endpoint `https://polza.ai/api/v1` и модель `baai/bge-m3`. BGE-M3 поддерживает многоязычный поиск и имеет лицензию MIT, поэтому может быть развёрнута локально через совместимый inference-сервис. При недоступности endpoint остаётся лексический поиск.

Вопросы и идентификаторы пользователей не сохраняются. В локальный журнал на 7 дней попадает только результат поиска, ID документов, подразделение и тип события. Публичная панель показывает только агрегаты. Обратная связь содержит только фиксированную оценку без текста.

## Проверка качества и задержек

Запустить автоматические проверки: `node --test`. Диагностика retrieval доступна только с `QUALITY_ADMIN_TOKEN`; ответ пользователю не содержит внутренние причины отказа, ID чанков или текст найденных фрагментов. Не публикуйте локальные eval-файлы вместе с документами или секретами.

## Текущие границы

- Реестр и поиск работают по локально подготовленному корпусу, без интеграций с Confluence/CRM/DION.
- Обращение без найденного/понятного ответа требует явного согласия и адреса для ответа. При настроенном Gmail SMTP письмо отправляется на `QUALITY_EMAIL`, сотрудник ставится в копию, а его адрес используется как Reply-To. Нужен Google App Password, обычный пароль аккаунта не подходит. Без настроек письмо не отправляется, а обращение попадает в локальную демо-очередь на `/quality`.
- Демо-очередь хранит текст обращения до 30 дней, логи — до 7 дней. Для реального пилота нужны согласованные сроки и канал уведомления.
- Опыт коллег появляется только из `data/verified_experiences.json` и только после проверки службой качества; неподтверждённые отзывы не выдаются как правило.
- Данные демо обезличены. Не размещать секреты или корпоративные исходники в публичном репозитории.
- Для конкурсного стенда сверить допустимость внешнего inference API; продукт должен быть переносим на локально разворачиваемую модель.
